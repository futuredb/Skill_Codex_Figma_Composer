# Figma Composer

`Figma Composer` превращает UI-референсы в Figma в структурированные и редактируемые экраны. Навык разбирает композицию и материалы, сохраняет описание референса для других агентов и проверяет результат с помощью арт-директора. По запросу создаёт дубль в коде.

## Как подготовить файл

1. Поместите каждый UI-референс отдельным изображением внутрь собственного Figma Frame.
2. Настройте размер, скругления, Corner smoothing и clipping внешнего Frame — эти свойства будут сохранены в итоговом экране. Названия Frame и слоя изображения могут быть любыми.
3. Для нескольких экранов используйте отдельный Frame для каждого референса. Для максимальной точности рекомендуется обрабатывать один сложный референс за запуск.
4. Для фотографий и другого растрового контента навык сначала использует изображения, уже доступные в компонентах и слоях этого Figma-файла, включая другие страницы. Папка `figma-compozer/assets/` служит запасным источником.
5. Передайте Codex ссылку на Figma-файл, нужный node или выделенную область. Область реконструкции должна однозначно указывать на нужные UI-референсы; поиск изображений на других страницах не добавляет новые экраны в обработку.

Запустите навык:

```text
Используй $figma-compozer для этой Figma-ссылки: <ссылка>
```

## Откуда берутся изображения

Для фотографий, аватаров, иллюстраций и других растровых материалов действует следующий порядок:

1. Изображения из компонентов, экземпляров и других слоёв переданного Figma-файла. При необходимости поиск продолжается на других страницах этого же файла.
2. Изображения из `figma-compozer/assets/`, только если в Figma-файле нет доступных пригодных изображений.
3. Градиентная заглушка, если оба источника недоступны или пусты.

Подбор по смыслу необязателен: допустим случайный, последовательный или смысловой выбор. Навык использует разные доступные изображения, прежде чем повторять их, и переиспользует их в новых контейнерах без изменения исходных компонентов и слоёв. Геометрия и оформление контейнеров восстанавливаются по референсу.

Полные скриншоты интерфейсов не используются как фотографии или источник вырезанных фрагментов. Иконки собираются отдельно как редактируемые векторы.

## Что будет на выходе

Для каждого референса навык создаст рядом отдельный редактируемый экран `Screen 01`, `Screen 02` и далее. Исходные референсы и посторонние слои останутся без изменений.

Экран сохраняет размеры и геометрию исходного Frame. Интерфейс собирается из нативных слоёв Figma и Auto Layout: редактируемых текстов, векторных иконок, изображений, заливок, градиентов, обводок, теней и blur-эффектов.

Референсы обрабатываются последовательно. После сборки выполняется визуальная проверка и до трёх циклов исправлений. Если расхождения остаются или проверка недоступна, это фиксируется в отчёте перед переходом к следующему референсу.

## Сложные материалы

Навык разбирает поверхности по слоям: фон, заливки и градиенты, прозрачность, blur, контуры, блики и тени. Различает размытие фона и самого объекта, проверяет сложные материалы по фрагментам и на уровне всего экрана.

Неоднозначные варианты сравниваются на восстановленном фоне. По одному скриншоту не всегда можно определить исходные параметры эффектов, поэтому предположения, уверенность и ограничения сохраняются в описании референса.

## Описание для другого агента

Для каждого референса в рабочей папке создаётся `reference-packs/<reference-id>/`:

- `reference.md` — описание композиции, материалов и решений для человека или другого агента.
- `reference.json` — оригинал, структура, токены, компоненты, композиция, поведение, теги, реконструкция и качество.
- `art-direction.md` — ключевые визуальные принципы и критерии проверки.
- `art-review.md` — замечания арт-директора, история исправлений и итоговый вердикт.

Наблюдаемые свойства отделяются от предположений. Анимации и взаимодействия, которые нельзя установить по статичному изображению, отмечаются как неизвестные.

## Проверка арт-директором

Арт-директор сравнивает фактические скриншоты результата с оригиналом: композицию, иерархию, типографику, пропорции, материалы и технические дефекты. Он проверяет точность реконструкции, не меняя стиль по своему вкусу.

Когда доступна делегация, проверку выполняет отдельный агент. Иначе отчёт явно отмечает самопроверку. За проход выделяются три наиболее значимые проблемы с конкретными исправлениями и критериями проверки. После исправлений оценивается новый скриншот; автоматический цикл ограничен тремя итерациями на референс.

Вердикты:

- `pass` — критерии выполнены, известных исправимых визуальных дефектов нет.
- `pass_with_notes` — остались небольшие замечания или явно описанные приближения.
- `needs_revision` — остались существенные проблемы, в том числе после исчерпания лимита исправлений.
- `unverified` — исходное изображение или скриншот результата недоступны для визуальной проверки.

## Дубль в коде

По запросу навык создаёт код из той же модели референса: в стеке текущего проекта либо как самостоятельный HTML/CSS в пустой рабочей папке. Браузерный результат проверяется отдельно относительно оригинала; одобрение Figma-версии не означает одобрения кода.

```text
Используй $figma-compozer для этой Figma-ссылки: <ссылка>.
Сохрани описание референса и создай дубль в коде.
```
